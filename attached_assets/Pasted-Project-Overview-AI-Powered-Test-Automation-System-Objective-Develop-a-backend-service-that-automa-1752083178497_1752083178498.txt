Theoretical Explanation of the Workflow Objective: The system automates the generation and execution of test cases based on user stories, starting with a base URL provided by the user. The workflow involves scraping the target website, generating test cases, executing them, and reporting results. Workflow Steps User Input: Base URL and User Story The user provides the base URL of the website to be tested along with a user story that describes the functionality to be validated. This input serves as the foundation for the entire testing process. Parse User Story The system begins by parsing the user story. This involves formatting the input to prepare it for interaction with the AI model. Generate Test Cases The formatted user story is sent to a Large Language Model (LLM) with a prompt to generate relevant test cases. The interaction with the LLM follows these steps: Prepare Prompt: The user story is formatted into a structured prompt. Call LLM: The system requests the LLM to generate test cases based on the user story. Extract Test Cases: The LLM returns a numbered list of test cases (e.g., "1. TC1: Verify login"). Queue Test Cases: The extracted test cases are stored in a queue for execution. Initial Scrape The system initiates the first test case by performing an initial scrape of the provided base URL: Load Page: The Playwright library loads the specified URL in a headless browser. Setup Mutation Observer: A MutationObserver is initialized to track changes in the DOM during test execution. Prune HTML: The initial DOM is cleaned to remove unnecessary elements (e.g., scripts, styles) to focus on relevant content. Generate Selectors The system analyzes the pruned HTML to generate selectors for the first test case: Analyze Elements: The system identifies relevant nodes in the DOM that correspond to the actions defined in the test case. Map Selectors: The identified elements are mapped to user-friendly names (e.g., login_btn mapped to button.primary). Generate Script The system composes a Playwright script based on the generated selectors: Compose Actions: The script includes actions to be performed (e.g., page.click(selectors.login_btn)). Validate Against Schema: The generated script is validated against a Zod schema to ensure correctness and prevent runtime errors. Execute Script The generated script is executed in the headless browser: Run Playwright: The Playwright library executes the script, performing the defined actions. Capture Mutations: The MutationObserver captures any changes in the DOM during execution. Calculate Delta: The system compares the current DOM state with the baseline to identify changes. Merge Changes: The system applies any changes detected during execution to the DOM. Mutation Observer The MutationObserver tracks various types of changes: Track Added Nodes: Records newly added elements. Track Attributes: Monitors changes to attributes of existing elements. Store Changes: Captures old vs. new values for modified attributes. Store Results After executing the test case, the results are stored: Check Queue: The system checks if there are more test cases to execute. If a test case fails, the execution halts, and no further test cases are run. Generate Report Once all test cases have been executed (or halted due to a failure), the system generates a detailed HTML report: Compile Evidence: The report includes screenshots, logs, and a summary of test results. Post to Jira (Optional): If integrated, the report can be attached to the corresponding Jira ticket for tracking. Key Concepts and Notes LLM Interaction: The LLM is crucial for generating test cases based on user stories, allowing for dynamic and context-aware test creation. Delta Capture: The MutationObserver records changes in the DOM, enabling the system to understand how the page state evolves during test execution. DOM Patching: The system applies changes detected during execution to the DOM, ensuring that the test results reflect the current state of the application. Error Handling: If any test case fails, the system stops executing further test cases, providing immediate feedback to the user. By leveraging AI and headless browser technology, the system provides efficient and effective testing capabilities, along with detailed reporting to facilitate quick analysis and resolution of issues.
